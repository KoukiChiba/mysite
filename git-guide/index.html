◆ Section 01

Gitとは何か？

ファイルの変更履歴を管理する「バージョン管理システム」です。ゲームのセーブポイントのようなイメージで覚えましょう。

💾
バージョン管理とは？
ファイルの「いつ・何を・誰が」変更したかを記録するシステム。間違えても過去の状態に戻せます。

「昨日のバージョンに戻したい！」というときに大活躍します。
🎮
ゲームのセーブポイントと同じ
Gitの「コミット」はゲームのセーブポイントに相当します。

好きなセーブポイントに戻れるように、コードの特定の状態をいつでも復元できます。
💡

ポイント：GitはPC上で動く「ローカルなツール」です。インターネット接続がなくても使えます。後で学ぶGitHubはGitの内容をネット上に保存・共有するためのサービスです。

Gitの基本的な仕組み

📁
ワーキングツリー
実際に編集している作業フォルダ。普段ファイルを編集する場所です。
📋
ステージングエリア
コミット前に「記録する変更」を選んで並べる準備スペース。
🗃️
リポジトリ（.git）
変更履歴が保存される場所。git initで作成されます。
◆ Section 02

GitHubとは何か？

GitのリポジトリをインターネットでホスティングするWebサービス。コードのクラウド保存＋チームコラボレーションの場所です。

比較項目 🌿 Git 🐙 GitHub
種類ソフトウェア（ツール）Webサービス
動く場所あなたのPC（ローカル）インターネット（クラウド）
主な用途変更履歴の管理・記録コードの共有・チーム開発
インターネット不要必要
アカウント不要必要（無料あり）
☁️
バックアップの役割
PCが壊れてもGitHubにpushしてあればコードを失いません。いつでもどこからでもclone（ダウンロード）できます。
👥
チーム開発の中心
複数人で同じリポジトリを編集・管理できます。Pull Request（プルリクエスト）でコードレビューも簡単。
◆ Section 03

基本コマンド8選

まずはこの8つを覚えましょう。これだけで日常の開発は十分できます。

init 🌱
リポジトリを新規作成
現在のフォルダをGitの管理下に置きます。最初に一度だけ実行します。
$gitinit
Initialized empty Git repository in .git/
add 📋
変更をステージングに追加
コミットに含めたい変更を「ステージングエリア」に追加します。
$gitaddindex.html# ファイル指定
$gitadd.# 全変更を追加
commit 💾
変更を記録（セーブ）
ステージングの変更を履歴に記録します。メッセージは何を変更したか書きましょう。
$gitcommit-m"ヘッダーを追加"
[main abc1234] ヘッダーを追加
push ⬆️
GitHubにアップロード
ローカルのコミットをGitHubのリモートリポジトリに送信します。
$gitpushoriginmain
pull ⬇️
GitHubから最新を取得
リモートの最新変更をローカルに取り込みます。共有ブランチに他の人の更新があるか確認して、必要なときに実行しましょう。
$gitpulloriginmain
clone 📥
リポジトリをコピー
GitHubにあるリポジトリを自分のPCにまるごとダウンロードします。
$gitclonehttps://github.com/user/repo.git
branch 🌿
ブランチを作成・確認
本流（main）から分岐した「作業用コピー」を作ります。失敗しても本流に影響なし！
$gitbranchfeature/login# 作成
$gitswitchfeature/login# 移動
merge 🔀
ブランチを統合
作業ブランチで完成した変更を main ブランチに取り込みます。
$gitswitchmain
$gitmergefeature/login
◆ Section 04

GitHubでリポジトリを作る手順

実際にGitHubにコードをアップロードするまでの流れを確認しましょう。

1
GitHubでリポジトリを新規作成
github.com にログイン → 右上の「+」→「New repository」→ リポジトリ名を入力 → 「Create repository」をクリック

⚠️ 「Add a README file」「Add .gitignore」「Choose a license」はチェックせず空のまま作成してください。チェックすると次のステップでpushが失敗します。

2
ローカルフォルダをGitで初期化
プロジェクトフォルダに移動して実行。git add . の前に .gitignore を作成して、パスワードや秘密鍵・node_modules などをGit管理から除外しましょう。
$gitinit
$gitbranch-Mmain# ブランチ名をmainに統一
# .gitignore を作成してから add する
$gitadd.
$gitcommit-m"first commit"

💡 .gitignore とは？ Gitの管理から除外したいファイルを記述するファイルです。.env（環境変数）、秘密鍵、node_modules/ などを必ず記載しましょう。gitignore.io でテンプレートを自動生成できます。

3
GitHubのリポジトリを「リモート」として登録
ローカルとGitHubを接続します（URLはGitHubのページに表示されています）
$gitremoteaddoriginhttps://github.com/あなた/リポジトリ名.git
4
GitHubにプッシュ（アップロード）
ローカルのコミット履歴をGitHubに送信します。HTTPS接続の場合、Gitパスワード認証は廃止済みです。初心者には GitHub CLI が最も簡単です。
# GitHub CLI（推奨・最も簡単）
$ghauthlogin# ブラウザで認証するだけ

CLIを使わない場合は Git Credential Manager または Personal Access Token（PAT） も使えます。PATはGitHubの Settings → Developer settings → Personal access tokens で発行できます。

$gitpush-uoriginmain
✓ Branch 'main' set up to track 'origin/main'
🎉

完了！ これでGitHubのページを開くと、あなたのコードがGitHubに保存されています（Privateリポジトリの場合は自分だけが閲覧できます）。次回からは git add → git commit → git push の流れだけでOKです。

◆ Section 05

よくあるエラーと対処法

初心者がつまずきやすいエラーをまとめました。エラーが出ても慌てず対処しましょう。

エラー
Please tell me who you are（コミット時）
Author identity unknown
*** Please tell me who you are.
✅ 解決方法

Gitにあなたの名前とメールを登録します（初回セットアップ）

$gitconfig--globaluser.name"Your Name"
$gitconfig--globaluser.email"you@example.com"
エラー
nothing to commit, working tree clean
✅ 解決方法

これはエラーではなく「記録すべき変更がない」という正常なメッセージです。本当に変更がない場合は問題ありません。心当たりがあるのにこのメッセージが出る場合は次の点を確認しましょう。

  • ファイルを保存し忘れていないか（エディタで Ctrl+S / Cmd+S）
  • そのファイルが .gitignore の対象になっていないか
  • git add をしたフォルダが正しいか（別のフォルダを編集していないか）
$gitstatus# 現在の状態を確認
エラー
CONFLICT (content): Merge conflict in ファイル名
✅ 解決方法

同じ箇所を2人が異なる内容に変更した「コンフリクト」です。ファイルを開いて <<<<<<< と >>>>>>> の間を手動で編集し、残したい内容だけ残してから再コミットします。

# ファイルを編集してコンフリクトを解消後...
$gitadd.
$gitcommit-m"コンフリクト解消"
エラー
rejected — Updates were rejected (push時)
✅ 解決方法

GitHubの方が新しい変更を持っています。--rebase オプション付きで最新を取得してからpushします。単純な git pull は意図しないマージコミットが生まれることがあります。--rebase は履歴を直線的に保ちやすいのが特徴です。

$gitpull--rebaseoriginmain
# コンフリクトがなければそのままpush
$gitpushoriginmain

⚠️ コンフリクトが発生した場合：ファイルを手動で編集して解消した後、git commit ではなく git rebase --continue で rebase を再開します。

# コンフリクト解消後...
$gitadd.
$gitrebase--continue# commitではなくこちら
エラー
fatal: not a git repository
✅ 解決方法

Gitで管理されていないフォルダでコマンドを実行しています。正しいフォルダに移動するか、git init を実行しましょう。

$cdあなたのプロジェクトフォルダ
$gitinit
⚡ Section 06

コマンド チートシート

よく使うコマンドをまとめました。ブックマークして手元に置いておきましょう。

git init
リポジトリを新規作成
git status
現在の状態を確認
git add .
全変更をステージングへ
git add <ファイル>
特定ファイルをステージングへ
git commit -m ""
変更を記録（メッセージ付き）
git log --oneline
コミット履歴を簡潔に表示
git push origin main
GitHubにアップロード
git pull origin main
GitHubから最新を取得
git clone <URL>
リポジトリをコピー
git branch
ブランチ一覧を表示
git branch <名前>
新しいブランチを作成
git switch <名前>
ブランチを切り替え
git merge <名前>
ブランチをマージ
git diff
変更内容の差分を確認
git stash
変更を一時退避
git stash pop
退避した変更を戻す
